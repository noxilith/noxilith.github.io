DOCS/ELORANOTES

EloraNotes

The complete guide to EloraNotes: a calm, local-first Markdown notes app written in Rust with eframe / egui. Every note is a plain file on your disk, every feature works offline, and sharing is something you switch on rather than something the app assumes.

LINUX/MACOS/WINDOWS/GPL-3.0

01 Overview

EloraNotes keeps your notes as portable .md files with a short YAML frontmatter block. There is no database and no account: copy the folder and you have everything, open a note in any Markdown editor, or put the folder on a USB stick and carry it between machines.

The app is local-first by design. It works completely offline; it only touches the network when you ask it to — when it checks GitHub for a new release, when a note points at a picture on the web, or when you connect to a shared library. Settings, themes and window geometry are stored beside the notes, not in a server somewhere.

Sharing is optional and deliberately small. One machine runs elora-server; everybody else points the app at its address, port and password. Notes in that library edit live, with coloured carets and names, and each note can be open to everybody, closed to its owner, or shared with a few named people. The server keeps the library as ordinary .md files too.

What the app can do

  • Write Markdown with live rendering. Edit raw, work in Split View, or read in a clean Preview where tasks tick and wiki links open.
  • Format without memorising syntax. A formatting bar and a right-click menu insert headings, bold, italics, underline, strikethrough, code, lists, tasks, quotes, wiki links, text colours and glowing highlights.
  • Find things again. Folders, tags with counts, a filter menu, fuzzy search, pinned notes and a Trash that can restore.
  • Connect notes. Wiki links, backlinks, a note graph, and a report of every link that points at a note you have not written yet.
  • Keep pictures and tables in the note. Drop, paste or choose a picture; write pipe tables that align and export properly.
  • Take it with you. Export one note or the whole vault as a standalone HTML site, or import a folder of Markdown files.
  • Share a library. Live editing, presence, per-note privacy, and an identity that survives renaming and follows you to another computer.
  • Make it yours. Seven themes, per-part colour overrides, text size, glow strength, compact or tall note cards.
  • Update itself. The app checks GitHub on launch, verifies the downloaded build runs, and installs it the way this copy was installed.
THE SHORT VERSION

Install it, type, and everything is already saved. The rest of this page is for the day you want folders, a picture, a table, or a friend in the same note.

02 Getting started

Download a build for your platform from the latest release; Install lists the formats and the one-time macOS prompt. Launch it and the notes folder is created for you.

The first launch

On a fresh machine EloraNotes creates Documents/EloraNotes and seeds three notes so the window is not empty:

  • Welcome to EloraNotes — a short tour of the palette, views, tasks and daily note, with links to the other two.
  • Reading & Project Ideas — a scratch note the welcome note links to.
  • Daily Scratchpad — a second linked note.

They are ordinary notes: rename them, empty them or trash them. Nothing depends on them.

A first note in ten seconds

  • Press Ctrl N (Cmd N on macOS). A note titled Untitled appears, selected and ready to type.
  • Click the title and type a real one. Spaces are fine; the title is not a file name.
  • Write in the body. Everything is written to disk as you type — there is no Save button and no unsaved state to lose.
  • Press Ctrl E to see it rendered, Ctrl Shift E for side-by-side, and Ctrl K to jump to another note.

Where everything lives

WhatWhere
NotesDocuments/EloraNotes — C:\Users\<you>\Documents\EloraNotes on Windows
Settings.elora-settings.json inside the notes folder
Picturesattachments/ inside the notes folder
Markdown importPut files in Import/, then run the import command
HTML exportDownloads by default, or a folder you pick once and it remembers

Every install format uses the same folder, including the Flatpak, so the same notes open whichever build you launch. Notes and settings from the old default folders (~/.config/eloranotes, ~/eloranotes, ~/.EloraNotes) are copied in on first launch; the originals are left untouched and nothing already in the new folder is overwritten.

Using a different folder

Pass --dir, or set ELORA_NOTES_DIR, and the app uses that folder for notes and settings instead:

elora --dir ~/Notes
ELORA_NOTES_DIR=~/Notes elora

One folder is open at a time. Switching folders means relaunching with the other path; there is no vault switcher inside the window.

OFFLINE UNLESS YOU SAY OTHERWISE

The only automatic network request is the update check against GitHub on launch (and it stays silent when offline). Pictures with http(s) sources are downloaded when a note is drawn, and a shared library connects only when you press Connect.

03 The window

The window is two panes: a fixed, narrow sidebar of notes on the left and one note on the right. There are no tabs and no split panes of different notes; the note you select is the note you have open.

The sidebar

  • The logo row holds elora notes and the accent New button. The sidebar does not resize, so the list never shifts around while the window does.
  • Search filters the list as you type. It looks at titles, bodies and tags; see Tags, search and sort for the exact rules.
  • Notes, Pinned and Trash switch sections and carry live counts. The trash button appears once something is in the Trash or you are looking at it.
  • Filter opens one menu of every tag with how many notes carry it. The small arrows button beside it orders each group by last edited, created or title.
  • The list draws pinned notes first, then the shared library and its folders, then local folders alphabetically, then unfiled notes under All Notes, then the Trash.
  • The footer holds four buttons: today's daily note, the command palette, the Ko-fi tip jar (which opens ko-fi.com/noxilith in your browser), and Settings.

The note header

Above the title sits one row of controls that belong to the open note:

  • Focus hides the sidebar; while hidden the same button says Sidebar and brings it back.
  • Note icon opens a searchable picker of Tabler glyphs, shows the chosen glyph on the note's card, and can remove it again.
  • Folder menu files the note under an existing folder, creates a new one, takes it out of its folder, or moves it to a shared library.
  • Lock — only on a shared note — opens Who can see this note.
  • Statistics show when the note was last edited, its word and character counts, an estimated reading time, and task progress such as 2/3.
  • Pin, view toggles, copy and trash: pin the note, switch between Edit, Split and Preview, copy its Markdown, or move it to the Trash (with a confirmation).

The title is a normal text field. Renaming changes the note's title — the card, the editor heading and exports — but not its file name on disk. Wiki links match the title, not the file, so a link that spells the old title stops resolving; the broken-link report lists them.

Under the title

  • Tag chips with an + add #tag field. Click a chip to filter by it, or its × to remove it.
  • The find bar, when open, with the match count and previous/next arrows.
  • The formatting bar, unless you turned it off in Settings.
  • The editor or, in Preview, the rendered note.
  • Linked from at the bottom lists every note whose wiki links point here; click one to jump to it.
  • On a shared note, a presence row above the editor shows who else has it open right now.

Short messages — "Copied Markdown to clipboard", "Imported 3 note(s)", a failed save — appear as a floating notice and fade by themselves. Focus mode keeps them inside the window instead of running off the edge.

04 Writing and saving

Put the caret in the body and type. Each change is persisted to the note's .md file straight away, so closing the window, losing power or killing the process cannot lose what you already wrote. There is no draft state and no Save button.

What the editor does for you

ActionWhat happens
TabIndents the caret's line, or every line the selection touches, by one level.
Shift TabTakes one level of indentation away from the same lines.
EnterStarts the next line with every quote and list marker the current line is nested in: a bullet stays a bullet, 1. becomes 2., a finished task comes back unchecked. On an empty item or quote it removes just that level instead of leaving an empty one.
Shift EnterStays inside the same item or quote: a plain new line with no repeated marker, lined up under the item's text.
Ctrl ZUndo, per note. Ctrl Shift Z or Ctrl Y redoes.
Ctrl VA copied screenshot or picture file is added to the note as an attachment instead of being pasted as text.
Right-clickThe formatting menu, including glow presets and text colour, at the caret or over the selection.

Indentation is spaces, so the Markdown looks the same in any other editor. A list inside a quote inside a list item keeps every level when you press Enter; Shift Enter keeps the markers it is inside and lines the text up under them. Undo history is kept per note for the session; it is not written to disk, so reopening the app starts a fresh history.

New notes

New creates a blank note titled Untitled. It joins the folder of the note you had open, and it keeps the tag you are filtering by, so a note made while looking at #project starts life as a project note. Made while Pinned is selected, it starts pinned. While a shared note is open, New creates the note on the server rather than on your disk.

Copying a note out

The copy button in the header (or Copy Current Note Markdown to Clipboard in the palette) copies the note as a complete Markdown document, with its title as a # Heading above the body. It is the quickest way to paste a note into a chat, an email or another app.

A NOTE ABOUT EXTERNAL EDITS

The app reads notes at startup and writes the open note as you type. If you edit a .md file by hand, do it while EloraNotes is closed; an open note in the app will overwrite the file on its next keystroke. The shared server re-reads a note's body when it is next opened, so its files can be edited between sessions too.

05 Files on disk

Every note is one .md file:

---
title: "Reading & Project Ideas"
pinned: false
trashed: false
tags: [reading, ideas]
folder: "Someday"
icon: book
created_at: 2026-10-24T09:12:44.318Z
updated_at: 2026-10-24T11:03:10.904Z
---
Books, tools and things to build.

- [ ] Finish **The Design of Everyday Things**
- [x] Try [[Pipe Tables]] in a real note

#reading #ideas

The block between the two --- lines is the note's metadata; everything after it is the body you write. A file without frontmatter still opens — its title comes from the file name — and is given frontmatter the first time the app saves it.

FieldMeaning
titleWhat the card, wiki links and export call the note.
folderThe folder it is filed under; absent means unfiled.
pinnedWhether it sits in the Pinned section.
trashedWhether it is in the Trash. The file stays in the folder.
tagsTags assigned with the chips. Inline #tags in the body count too.
iconThe Tabler glyph shown on the card and in the header.
created_at, updated_atTimestamps used by the Created and Last edited sort orders.
owner, owner_keyOn a shared note: who owns it, and the public key that decides it.
private, shared_with, shared_keysOn a shared note: whether it is restricted, the names to print, and the keys allowed in.

File names

A new note is named from its title plus the moment it was created, for example meeting-notes-20261024-091244.md. The name is fixed at creation: renaming the note changes title:, not the file, so backups, pictures and the server's copy keep a stable path. Wiki links match titles rather than file names, so renaming a note can still break a link that spells the old title. Two notes created in the same second get a numeric suffix.

The settings file

.elora-settings.json holds the theme, text size, colour overrides, glow, card style, sort order, folded folders, the window's size and position, the last export folder, and — if you use a shared library — the server address, password, your display name and your identifier. It is plain JSON, not encrypted, so treat the notes folder like you would a password file if you have connected to a server. Deleting the file resets the look and the connection; deleting it does not touch any note.

Pictures and the Import folder

  • attachments/ holds every picture added by the button, a drop or a paste. Notes refer to them by relative path.
  • Import/ is where you drop .md files for the import command. It is created the first time you run an import.
  • Nothing else is added to the folder by the app. There are no caches or databases to clean up.

To back up your notes, copy the whole folder; a shared library is a folder too. Keep the server's own data folder as well if you run one — it holds the certificate, the people list and the library.

06 Markdown reference

EloraNotes understands a focused dialect of Markdown. The table below is the whole language.

WriteGet
# HeadingA first-level heading. ## and ### are drawn at their own sizes in Preview; all six levels are real headings in the HTML export.
**bold**Bold.
*italic*Italic.
***both***Bold and italic together.
__underline__Underlined text.
~~gone~~Struck through.
`code`Inline code, drawn in the monospace face.
==glow==A highlight in the glow colour from Settings, halo included.
=={#4ECDFF}cyan glow==A highlight in that exact colour; the value is #RRGGBB.
{color:#FF7A90}red text{/color}Text in that colour. Close it with {/color}.
[[Note Title]]A wiki link to that note.
[[Note Title|shown words]]A wiki link that reads differently from its target.
#tagA tag. It must start with a letter; letters, digits, -, _ and / are kept, and the tag is lowercased.
- item or * itemA bullet list item, drawn with a dot.
1. itemA numbered list item. The editor counts it on when you press Enter; the number stays part of the text.
- [ ] taskAn unchecked task, clickable in Preview and Split.
- [x] taskA checked task, struck through and counted in the note's progress badge.
> quotedA quote block, drawn with the theme's accent bar.
``` … ```A fenced code block. Everything inside is literal: no formatting, tags or links.
--- or *** on its own lineA horizontal divider in Preview.
![alt](attachments/pic.png)A picture. See Pictures for paths, resizing and the {width=…} suffix.
| a | b | plus a | --- | --- | lineA table. See Tables for alignment and nesting.

Markers stack

Inline markers nest in any order and come out as one run carrying every style. All of these work:

**==bold inside a glow==**
==**glow then bold**==
***==triple stack==***
{color:#4ECDFF}**colored bold**{/color}
{color:#FF7A90}==red glow=={/color}

Headings carry highlights and colours too, so a heading can be emphasised without giving up its size. Code blocks are the exception: inside a fence the markers are just characters.

What is not supported

There are no footnotes, no reference-style links and no raw HTML passthrough. A <div> written in a note is shown as the characters you typed. The HTML export turns the same Markdown into HTML, so an exported page needs nothing from the app.

TAGS ARE READ FROM THE BODY

#daily counts as a tag wherever it appears outside a code fence, as long as it starts a word and begins with a letter. That is why the tag list fills itself as you write, without opening the chip field.

07 Formatting bar

The bar under the tags is a row of buttons that act on the selection, or insert at the caret when there is none. Settings → Show formatting bar hides it; the shortcuts and the right-click menu keep working.

H1, H2# and ## at the start of the line.
Bold, Italic, Underline, Strikethrough**…**, *…*, __…__, ~~…~~ around the selection.
Inline codeBackticks around the selection.
Bullet listStarts the selection (or the caret's line) with - .

Wiki link[[…]] around the selected words.

Markers stack: wrapping an already-formatted selection in another style adds to it, and applying the same style twice removes it again. The tooltip on each button names the shortcut where one exists.

Right-click in the editor

The context menu carries the same operations and the ones that do not fit on the bar: bold, italic, underline, strikethrough, inline code, glow highlight with four presets (Amber, Emerald, Cyan, Rose), a custom glow picker, text colour, headings, tasks, quotes, code blocks, a wiki link and clear formatting. Right-clicking with words selected formats those words; right-clicking with no selection inserts the marker at the caret.

Glow highlights

A highlight is not a flat background: it carries a soft halo whose strength is the Glow strength slider in Settings (0 turns the halo off; 0.6 is the default). The Default glow color swatch is what the toolbar button and plain ==text== use. A per-highlight colour written as =={#RRGGBB}text== overrides it for that run, and the right-click presets set the default for the next highlight.

Text colours are ordinary Markdown, so they survive edits in another editor, exports and a shared note; the app only decides how they look.

08 Pictures

There are three ways in, and they all end the same way: the file is copied into the notes folder's attachments/ directory and a picture line is written where the caret was.

  • The picture button in the formatting bar opens the system file chooser.
  • Dropping a file anywhere on the window adds it to the open note.
  • Pasting with Ctrl V (a copied screenshot, for example) saves the clipboard image as an attachment.

PNG, JPEG and GIF files are accepted. The note keeps a relative path such as ![sunset](attachments/sunset-20261024-101500.png), which means the folder stays portable: move it, copy it or open the export and the picture still resolves.

How pictures are drawn

![alt](source) works the way it does on GitHub. The source may be:

  • a path relative to the note's folder, including spaces (written with %20 or inside <…>);
  • an absolute path, or a file:// URL;
  • an http(s) URL, which is downloaded in the background and cached while the app runs.

A picture written next to words stays next to them; a picture on its own line gets its own line. In a quote, a picture is drawn inside the quote with the > marker left off. In a table cell it is fitted to the column (see Tables).

Resizing

In Preview or Split, drag the square handle in a picture's bottom-right corner. The width is written into the note as a {width=320} suffix after the picture, so the size is there the next time the note opens, on another computer, and in a shared note.

Pictures in a shared note

When the note lives on a server, the picture is uploaded too, and everybody with the library can see it even after the computer that added it is gone. A picture already in a local note travels with the note when you move it to the shared library, and Copy to this computer brings copies of its pictures along. The server accepts pictures up to 12 MB each; a larger one is refused rather than silently dropped.

THE FILE IS THE PICTURE

An attachment is an ordinary file in attachments/. Deleting it outside the app leaves the note pointing at nothing, so the picture can no longer be drawn. Backups that copy the folder keep the pictures.

09 Tables

A table is a header row, a delimiter row, and any number of body rows:

| Feature | Shortcut | Where |
| :--- | :---: | ---: |
| Preview | Ctrl+E | Header |
| Split | Ctrl+Shift+E | Header |
| Find | Ctrl+F | Above the editor |

Both of the first two lines need pipes; that is what tells the parser this is a table rather than a paragraph. The delimiter row also sets each column's alignment: :--- left, :---: centre, ---: right. A column with no colon is left-aligned.

What fits in a cell

Cells are parsed like any other line: bold, italics, underline, strikethrough, inline code, highlights, text colours and wiki links all work. A short or long row is padded or trimmed to the header's number of columns, so a missing pipe does not break the layout. Pipes inside inline code are still cell separators — escape them by keeping code short or putting the code in a paragraph above the table.

Pictures work too. A picture in a cell is fitted to that column's width and can be dragged to resize like any other; the column widens around it rather than the picture spilling over.

Tables inside quotes and lists

A table written on quoted lines is drawn inside the quote:

> | Name | Value |
> | --- | --- |
> | threshold | 12 |

Indent a table under a list item and it is drawn inside that item, one step in, in Preview, Split and the exported page. The same applies to a table inside a quote inside a list item.

Exporting

The HTML export writes a real <table> with the alignment on the cells and the header row as <th>, so it keeps its shape in any browser. A title underlined with --- is still treated as a heading, because a table needs pipes on both of its first two lines.

10 Views and find

The three view buttons sit in the note header, and the same modes are in the command palette.

ModeWhat it is
EditThe raw Markdown, with the formatting bar and find available. This is where you type.
Split (Ctrl Shift E)The editor and a live preview side by side. Edits appear in the preview as you type; tasks and wiki links are clickable on the preview side.
Preview (Ctrl E)The note rendered cleanly, with no Markdown markers. Task boxes tick, wiki links open notes, pictures resize.

Focus mode (Ctrl \, or the button in the header) hides the sidebar and leaves the note column in the middle of the window. The same button or shortcut brings the sidebar back.

Find in the open note

Ctrl F opens the find bar above the editor. It searches only the note in front of you, case-insensitively, and highlights every match on the page. The count shows where you are (2 / 7); Enter and the down arrow go to the next match, Shift Enter and the up arrow to the previous one, and Esc closes the bar. Moving to a match scrolls it into view.

Search the whole vault

Ctrl Shift F puts the caret in the sidebar search, and the field filters as you type. A query is split into words, and every word has to match somewhere:

  • a plain word matches a title (including a fuzzy subsequence), the body, or a tag;
  • a word starting with # matches only tags, and only ones containing that text;
  • an empty field shows everything, still narrowed by the active tag filter and section.

Results are ranked with a title match weighing far more than body matches, so the note you meant is usually at the top. Press Esc to clear the search, the tag filter and the section and return to All Notes; the little × in the field clears just the text.

Ticking tasks

In Preview and Split, click a task box. The note's Markdown is updated (- [ ] becomes - [x] and back), the line is struck through when done, and the progress badge on the note card and in the header changes with it. In Edit mode the box is just text.

11 Wiki links, backlinks and the graph

Write [[Another Note]] anywhere in a body to point at that note. Write [[Another Note|read this instead]] when the sentence needs different words from the title. Matching is case-insensitive and prefers the note's title; a link to a title that does not exist yet is still drawn as a link, and clicking it creates the note.

Following a link

In Preview or Split, click a wiki link. If the note exists it opens; if it does not, EloraNotes creates it with the body Linked from another note. plus the #linked tag, and opens it ready to write. The link target is the note's title, so renaming either note can break a link — the broken-link report below is how you find those.

Backlinks

The Linked from footer under the editor lists every note whose body contains a link to this one. Click a title there to jump to the note that mentions it. Backlinks are computed from the notes currently loaded, so they update as you write.

The note graph

Show Note Graph in the command palette opens a window with every live note on a ring, one dot per note and one line per wiki link. Hover a dot to highlight it, and click it to open that note. Trashed notes are not in the graph. It is a map of what links to what, not a second editor.

Links that lead nowhere

Show Links That Lead Nowhere lists every wiki-link target with no note behind it, together with the notes where it was found. Click a target to create that note and open it, which is the fix for most of them. The same report is the quickest way to find a link broken by a rename.

Links in exports

An HTML export rewrites wiki links to the exported pages. A single-note export brings the notes it links to and the notes that link to it, so its links open real pages; a link to a note outside the export stays the words it was written with rather than becoming a dead link.

12 Folders

Folders group the sidebar without moving files: a folder is the folder: value in a note's frontmatter, so every note stays in the same flat directory on disk. That keeps paths, pictures and backups simple while the list still reads like a tree.

Filing a note

Open the folder menu in the note header (it shows No folder until you pick one). The menu lists every existing folder, a New folder… field with an Add button, and No folder to take the note out. A new note created while a note inside a folder is open joins that folder automatically.

How folders look

  • Folders are listed alphabetically, each with its note count.
  • Their notes sit one step in from the header, so it is obvious what belongs to what.
  • Click a folder header to fold it shut; click again to open it. The folded state is remembered between launches.
  • While a search or tag filter is active, folders open themselves so matches are not hidden inside a folded one.
  • Unfiled notes appear under All Notes; pinned notes appear above everything, whatever folder they are in.

Folders in a shared library

A shared library has folders of its own. The library itself is marked with a cloud rather than a folder, and its folders sit one step in from it, with their notes one step further in again — deeper than a local folder, so a server folder is never mistaken for one on this computer. Everyone with the library sees the same folders and the same notes in them.

13 Tags, search and sort

A tag can be written in the body as #project, or added with the tag chips under the title. Both kinds are equal: the chip row shows the tags the note has, and the body keeps its own words. Typing a tag into the chip field and pressing Enter adds it; the × on a chip removes it from the note (an inline tag can only be removed from the text).

Tags are normalised to lowercase, and a leading # is optional when you type one. Tags may contain letters, digits, -, _ and /, which allows names like #project/elora. A code fence is ignored, so example tags in code do not pollute the list.

The filter menu

Filter in the sidebar lists every tag with the number of notes carrying it, in one scrollable menu. Pick one to narrow the list to that tag; pick it again, or choose All notes, to clear the filter. The button shows the active tag in the accent colour. Filters apply inside the current section, so a tag filter and Pinned work together.

Sorting

The arrows button beside the filter chooses the order for each group of notes:

  • Last edited — the default, most recent first.
  • Created — newest note first.
  • Title — alphabetical, case-insensitive.

The order applies within pinned, inside each folder, inside the shared library and its folders, and to unfiled notes. The folders themselves stay alphabetical, and pinned notes stay above everything. The choice is saved with the rest of the settings.

14 Pin, cards and trash

Pinning

Ctrl P, the pin button in the header, or Pin / Unpin Current Note in the palette pins a note. Pinned notes get their own section at the top of the sidebar, painted in the theme's pin colour, and stay in that section whatever folder they are in. Unpinning puts the note back where its folder and date say it belongs.

Note cards

The sidebar has two card styles. The default is a compact one-line row: a small icon and the title, so about twice as many notes fit in the list. Hovering a row shows when it was last edited and its tags.

Settings → Tall note cards brings back the taller card, with a date and a tag row. On those cards, Settings → Show a preview line on note cards adds the first lines of the note; it is off by default and has no effect on the compact rows, which have no room for it.

Both styles show a note's own Tabler icon, and — on a shared note somebody else has open — a small brush in each person's colour, which names them on hover. A tall card also carries the date, its tags and a task progress badge such as 2/3. Clicking anywhere on a card opens the note; the title is part of the card, so clicking it does not select the text instead.

Trash

The trash button in the header asks for confirmation in place (Move to Trash / Cancel), then marks the note trashed. Its file stays in the notes folder with trashed: true; it leaves the count, the graph and exports, and appears under Trash in the sidebar.

Open a trashed note and the header offers Restore and Delete Forever. Restoring puts the note back as it was, folder and tags included; deleting forever removes the file from disk. Nothing is purged on a timer, so the Trash keeps its contents until you decide.

15 Daily notes and templates

Ctrl D, the calendar button in the footer, or Open Today's Daily Note opens the note titled Daily Note — YYYY-MM-DD. If today's note exists it is opened; otherwise it is created from the daily template. Running it twice in one day never makes a duplicate.

The daily template starts you with morning intention tasks, a captures section, an end-of-day reflection, and the tags #daily and #journal:

## Friday, Oct 24 · Morning Intention
- [ ] Primary focus for today
- [ ] Secondary task

## Notes & Captures
-

## End of Day Reflection
> What went well today?

#daily #journal

Templates

Two more templates live in the command palette. New Note from Template: Meeting Notes creates a note titled with today's date and sections for attendees, agenda and action items, tagged #meeting and #notes. Project Spec creates a note with overview, goals, and an architecture section that links to [[Welcome to EloraNotes]], tagged #project and #spec.

Templates are just starting points. Once the note exists it is an ordinary note; edit or delete any part of it.

While a shared note is open, daily notes, templates and links that create a note all create it in the shared library instead of on your disk, so a team's daily note lands where the team can see it.

17 Export and import

Exporting to HTML

Export Current Note as HTML and Export All Notes as HTML are in the command palette. Neither writes anything immediately: a dialog first says exactly what would happen — how many pages and pictures it would write, whether it is the note and its linked notes or the whole vault, and the folder — and only the Export button writes. Cancel writes nothing.

  • Where: Downloads by default; a whole-vault export goes into an EloraNotes Export folder there. Choose… picks another folder, and the choice is remembered for the next export.
  • Pages: one standalone HTML file per note, with the note's title as the heading and a small built-in stylesheet, so it reads in any browser without the app.
  • Pictures: copied into a pictures folder beside the pages and written as real <img> elements. A picture that lives on the web is loaded from where it lives; one that cannot be found stays the words it was written with instead of becoming a broken image.
  • Wiki links: rewritten as links to the other exported pages. A link to a note outside the export stays plain text, so there are no dead ends.
  • Single-note exports close over links: exporting one note also writes the notes it links to and the notes that link to it, so its links work from either direction. If it links to nothing and nothing links to it, the export is just that page.
  • Tables, tasks and formatting are exported as HTML: real <table> elements with alignment, disabled checkboxes for tasks, and the inline styles the preview shows.

An export is a snapshot, not a sync folder. Editing an exported page does not change the note, and exporting again overwrites the pages it writes.

Importing Markdown

Put .md files directly inside an Import folder in your notes folder, then run Import Markdown From Import Folder. Each file becomes a new note: its frontmatter is kept (title, folder, tags, pin, icon and timestamps where present), its body is kept, and it gets a fresh file name so an existing note is never overwritten. The palette reports how many notes were imported; importing the same files twice creates duplicates.

The import is one level deep — files directly in Import/. Subfolders are left alone. After importing, the originals remain in Import/; delete them yourself once you are happy.

18 Shared notes

Shared notes are optional. One machine runs elora-server, which holds a library of ordinary .md files; the app connects to it over TLS and shows that library in the sidebar as a group titled with the server's name and marked with a cloud. There is no cloud account in between: the client talks straight to your server.

Connecting

Server setup is in Hosting a server. In the app, open Settings → Shared library and fill in:

  • Address — an IP or a DNS name. It also accepts host:port if you would rather type the port there.
  • Port — 7331 unless the server was installed on another one.
  • Password — the one the installer asked for. It is sent inside the TLS connection, never in the clear.

Press Connect. On the first connection the server presents a self-signed certificate and the app shows a short code; it must match the code the installer printed. Accept it once and the key is remembered: a different certificate on a later connection is refused. If the server legitimately gets a new certificate, Forget this server's key makes the app ask again next time. The state line under the heading says Not connected, Connecting… or Connected to <server> as <you>; a failure is explained under it instead of only flashing by in a notice.

Putting notes in the library

With a server connected, the note header's folder menu grows a Shared libraries section naming the server. Picking it moves the note there: its body, folder, tags, pin and icon arrive on the server, and the local file goes away once the server has it. The other direction is Copy to this computer in the same menu on a shared note, which keeps the shared note where it is and writes a local copy.

While a shared note is open, New creates the next note directly on the server, in the same folder and with the tag you are filtering by. Daily notes, templates and wiki links that create a note do the same. The new note appears on everybody's sidebar straight away.

Pictures added to a shared note are uploaded to the server and kept beside its notes, so everyone sees them and they survive the computer that added them. A picture already in a note travels with it when the note is moved in, and copying the note out brings copies of its pictures.

Editing together

Everyone who opens the same note sees each other's edits as they are typed. A coloured caret with the person's name marks where they are, their name is listed in the Editing with row above the editor, and their note card shows a brush in their colour while they have it open. Colours come from the colour each person chose, so the same person keeps the same colour.

The merge is a proper shared document, not last-writer-wins. A keystroke made against a frame that has not yet drawn somebody else's new words is placed on the text it was actually made on, so the other person's words stay. The caret is sent at a short interval and the held-back last position is sent as soon as it may be, so a name tag does not sit a few characters behind fast typing. If two people replace exactly the same characters at the same instant, the other person's words are kept and your replacement goes in beside them; a second backspace fixes it rather than your typing being silently eaten.

The connection looks after itself. While a note is open the client pings the server every 20 seconds, so a quiet note is not mistaken for an abandoned connection and dropped for everybody at once, and a link that has genuinely died (a laptop that slept, a router that forgot the mapping) is noticed within about a minute and reconnected. After a reconnect the room's text is restored; anything typed during the gap is replaced by the room's text.

What syncs

  • Synced: note bodies, titles, folders, tags, pins, the trash state, and pictures in shared notes.
  • Local: themes, text size, colour overrides, card style, window size and position, the update check, and your local-only notes.
  • Not synced: anything outside the library. A note stays on your computer unless you move it into the shared library.
SAME PROTOCOL ON BOTH SIDES

Everybody in the library, including the server, needs a build that speaks the same protocol — 0.9.21 or newer. A client that can share pictures or enforce key-based privacy refuses an older server and says which side to update, rather than quietly leaving pictures out or trusting names.

19 Name, identifier and key

On a shared library you go by two things, both in Settings → Shared library. They do different jobs, and keeping them separate is what stops somebody from becoming you by typing your name.

Your name

The name is public. It is what others see next to your caret and in the share panel, and what they type to put you on a note. A fresh install suggests your account name with four random hex characters (noxilith-4f2a); you can replace it with any word. The first person to use a name on a server keeps it: the server refuses a name that is already claimed at the handshake, so two people cannot both be “Skorp”.

Your identifier

The identifier is the secret behind the name: 32 random hex characters generated once on this computer. Only the server ever reads it, to check that the connection really is the person the name belongs to. It is never sent to other clients, never written into a note, and the server keeps only its hash. Treat it like a password.

There is deliberately no “make a new identifier” button, because the server binds a name to the key that claimed it: a fresh secret would be a stranger, locked out of the name and out of every note restricted to the old key. If the identifier leaks, close the app, clear the identifier from .elora-settings.json (or delete the file), and the next launch generates a new one. Have the server operator free the old name first (people release). Notes that recorded the old key stay closed to the new one.

Your key

The identifier is turned into a public key, SHA-256(identifier), written as 64 hex characters. A note records the key — owner_key for its owner, shared_keys for its guests — never the identifier. The key cannot be turned back into the secret, which is why it is safe to show and copy. The short form beside Your key is a readable fingerprint of the full 64 characters, and the Copy button copies the whole value for the server operator when older notes have to be adopted.

Changing your name changes nothing

Noxilith who becomes Skorp is still the key behind Noxilith. The notes they own, the notes only they can see and the notes other people shared with them keep reaching them. Connecting as Skorp does not open Skorp's notes, because those belong to a different key — and a name taken from somebody reaches nothing of theirs. That is the point of the split: the name is a label, the key decides.

The same person on another computer

Press Copy beside the identifier here and paste it into the same box on the other computer. You arrive as the same person, with the same notes and restrictions. The display name is a separate field, so type the same one there if you want to go by the same label; the key is what decides access either way. Changes to the name or identifier restart the connection so the server can re-evaluate what it shows you.

Your colour

Your colour is the colour other people see your name and caret in while a note is shared. Pick any colour, or press Automatic to go back to the one derived from your name. It only changes what other people see; nothing in your own window changes. A colour picked while a note is open reaches the people already in it, and is remembered for the next connection.

20 Who can see a note

A note made in the shared library is open to everybody on that server. The lock button in its header opens Who can see this note:

  • Everyone on <server> — the whole library, which is where a new note starts.
  • Only me — nobody else's sidebar lists it and nobody else can open it. Anyone reading it when it is closed is taken out of it, so nothing typed afterwards reaches them.
  • Only these people — the same, plus the people named on the note. Type the name as it appears next to their caret (Their name, e.g. Goku) and press Add. The server knows which key owns that name, so the note reaches that person and not whoever else types the same word. A name nobody on the server has claimed is refused with “nobody on this server is called that” rather than quietly written down for whoever picks it up later. Remove a person's chip to take the note away again.

Only the note's owner changes this. Everybody else sees whose note it is and that it was shared with them; the controls are disabled. Ownership is recorded on every note the library creates, in its frontmatter (owner_key:, private:, shared_keys:), which the server keeps in the .md file, so a restriction survives a restart and stays visible to anyone who edits the folder by hand.

How the decision is made

What decides entry is a key, never a name. The server computes SHA-256(identifier) from the identifier a connection brings and compares it with owner_key and shared_keys. Names in the note are labels for the sidebar and the share panel. So one identifier on two computers is one person, and no other identifier is — changing a display name cannot move a note to a different person.

A restricted note with no key on it was locked before keys existed. It is handed to nobody over the network, because a name proves nothing. The server operator gives it a key once with elora-server people adopt --write, after checking the name list.

WHAT THE LOCK DOES AND DOES NOT DO

The server password still decides who may connect at all, and whoever runs the server can read its files. There is no end-to-end encryption: the server holds the notes in the clear so it can serve them. Treat the lock as which notes this server hands out, to which identity, for a household or group who trust each other with the password — and keep your identifier as private as the password.

21 Hosting a server

The server is a small binary with no GUI libraries, so it runs on a headless machine. Every release ships it with an installer for Linux and Windows.

FileWhat it is
elora-server-linux-x86_64The Linux server binary.
install-elora-server.shThe Linux installer.
elora-server-windows-x86_64.exeThe Windows server binary.
install-elora-server.ps1The Windows installer.

Linux

chmod +x install-elora-server.sh
sudo ./install-elora-server.sh

The installer asks for the name people see in their sidebar, the port, and the password everyone connects with. It installs the binary to /usr/local/bin/elora-server (or /opt/elora-server/elora-server when /usr/local is not writable), creates the notes folder, generates a self-signed certificate, registers a systemd service that starts at boot, and opens the port in ufw or firewalld when one of those is in charge. It finishes by printing the addresses to hand out and the short certificate code the first client will ask you to confirm.

On an immutable system such as NixOS, where /etc/systemd/system is read-only, the installer registers a service for your own account instead: the notes move to ~/.local/share/elora-server, lingering is switched on so it still starts at boot, and the summary prints the systemctl --user commands. Set ELORA_SERVICE_MODE=system or ELORA_SERVICE_MODE=user to force one. A certificate left by an interrupted install is carried over, so the code clients already trust does not change.

Windows

Open PowerShell as Administrator and run:

powershell -ExecutionPolicy Bypass -File .\install-elora-server.ps1

It asks the same questions, installs the binary, creates the notes folder and certificate, registers the startup task EloraNotes Server, and opens the port in Windows Firewall. Run it from an elevated shell so the task and the firewall rule can be created.

Where the server keeps things

The data folder holds config.json (name, port, bind address, the password, and the notes path — it is plain JSON, so protect the folder as you would the password), cert.pem and key.pem, people.json (which name belongs to which key), and the notes folder. The notes folder is an ordinary EloraNotes library with attachments/ inside it, so copying or backing it up keeps everything.

The server listens on all interfaces by default (bind: "0.0.0.0") on port 7331. Editing a note's file by hand works — the server re-reads a note's body when it is next opened — but an open note is held in memory, so edit between sessions rather than under a live one.

Updating, uninstalling and reinstalling

Running the installer again on a machine that already has a server is an update, not a second install. It prints what it found (service, binary, settings, how many notes, the certificate code) and asks whether to update it, uninstall it and keep the notes, uninstall it and delete the notes and certificate, or cancel. Updating keeps the notes and the certificate, so the code clients trust does not change.

For scripted installs, ELORA_ACTION=update, uninstall or purge skips the question (on Windows, set $env:ELORA_ACTION first). With no answer to the prompt, an existing install is updated.

Reaching it from another network

On the same LAN, use the machine's local address (192.168.1.20) and the port. From outside, forward that TCP port on the router once and give people the public IP or a DNS name; give the server machine a fixed LAN address so the rule keeps pointing at it. If the WAN address the router reports differs from curl -4 ifconfig.me, the connection is behind carrier-grade NAT and no port forward can work — put both machines on a VPN such as Tailscale and use the server's address there.

A DNS name works anywhere an IP does, and the client's address field accepts address:port.

22 Server upkeep

Keeping it running

# Linux
systemctl status elora-server
journalctl -u elora-server -f
sudo systemctl restart elora-server

# Linux, per-user install
systemctl --user status elora-server
journalctl --user -u elora-server -f

# Windows
Start-ScheduledTask -TaskName "EloraNotes Server"
Stop-ScheduledTask  -TaskName "EloraNotes Server"

Keep the app and the server on the same release. The library needs both sides to speak the same protocol, so a release that changes it leaves the older side refused until it is updated — and server-side fixes only arrive when the server is. Download the new elora-server from the release, re-run the installer (or replace the binary) and restart the service.

Who is who

elora-server people manages the name list — which display name is bound to which public key. Running elora-server people or elora-server people list prints every claimed name with its key. The short form beside Your key in Settings is yours.

elora-server people list
elora-server people adopt            # dry run: what would change, and for whom
elora-server people adopt --write    # apply it
elora-server people release Skorp    # free a name claimed by the wrong person

adopt is for notes locked before keys existed. It takes each restricted note's owner name, looks it up in the list, and writes the key behind it into the note; guests named on the note get their keys too. A name nobody has claimed cannot be turned into a key — have that person connect once, then run it again. release frees a name that was claimed by the wrong key; the next connection with that name claims it, so let that be its owner. Notes that already carry a key need nothing: their owner: line is only the label the sidebar prints.

STOP THE SERVICE BEFORE WRITING

A running server keeps its own copy of the library and the name list in memory and saves it again on the next connection or edit, which would undo a release or adopt --write. Stop the service for the minute it takes, run the command as the service user with the same data folder the unit names, then start it again.

# What this machine's service really uses (User=, Environment=, ExecStart=)
systemctl cat elora-server | grep -E '^(User|Environment|ExecStart)'

sudo systemctl stop elora-server
sudo -u elora env ELORA_SERVER_DIR=/var/lib/elora-server elora-server people list
sudo -u elora env ELORA_SERVER_DIR=/var/lib/elora-server elora-server people release Skorp
sudo systemctl start elora-server

elora and /var/lib/elora-server are the installer's defaults; the systemctl cat line prints the ones this machine really uses. A per-user install is systemctl --user, with ~/.local/share/elora-server and no sudo.

Run it as the service user, not root. sudo ELORA_SERVER_DIR=… elora-server … does not work — sudo reads VAR=value as the command name — and root would leave people.json owned by root, so the service could no longer save a name claimed afterwards. sudo -u elora env … sets it without changing the owner. After a release, people list shows the name free rather than gone: the next person to connect with it claims it.

Checking the build and the certificate

elora-server version
elora-server show          # the saved settings and the addresses to hand out
elora-server fingerprint   # the short code clients confirm, and the full fingerprint

If clients ask to confirm a new code after an update, the certificate changed and each client needs to accept it once (or use Forget this server's key first, then connect). Keeping the data folder intact during an update keeps the certificate, and therefore the code, the same.

23 Stuck on Connecting…

A wrong password or an outdated client says so by itself. Being stuck at Connecting… means the connection never got through; the app gives up on an address after a few seconds and shows the reason under the state line. The usual causes, in the order worth checking:

  • The server is not running. On the server machine: systemctl status elora-server, then journalctl -u elora-server -n 30 --no-pager.
  • It is listening on the wrong address. ss -ltn | grep 7331 should show 0.0.0.0:7331 or [::]:7331. 127.0.0.1:7331 means only that machine can reach it: set bind to 0.0.0.0 in the server's config.json and restart it.
  • A firewall drops the port. The installer opens it in ufw or firewalld; check sudo ufw status if you use another firewall, and check Windows Firewall on a Windows server.
  • The router does not forward it. Forward TCP 7331 to the server machine's LAN address, and give that machine a fixed address so the rule keeps pointing at it.
  • You are behind carrier-grade NAT. If the router's WAN address differs from curl -4 ifconfig.me, no port forward can work; use a VPN such as Tailscale and the server's address there.
  • The public IP does not work from inside your own network. Many routers cannot loop back to their WAN address; test from a phone on mobile data before assuming the port is closed.
  • The certificate code does not match. If the app refuses the server's key, you are talking to something else (or the server was reinstalled). Stop and check the code on the server with elora-server fingerprint; only then forget the old key and accept the new one.

A DNS name works anywhere an IP does. If the address field holds host:port, leave the port field matching it or clear the port from the address; both forms are accepted, and the explicit port in the address wins.

27 Updates

On launch the app compares its version with the latest GitHub release. When one is newer it offers Update now or Later; Later dismisses the prompt for that run, and a failed launch-time check (for example while offline) stays silent. Before installing, the downloaded build is started once to prove it runs on this machine.

What an update does depends on how the copy was installed:

  • AppImage — the new image is downloaded beside the old one, started once, then swapped in and relaunched.
  • Windows setup — the new installer runs silently over the old install, keeping shortcuts and the uninstall entry correct, and the app restarts.
  • macOS app bundle — the new EloraNotes.app replaces the old one, which is cleaned up on the next launch.
  • Portable exe or tarball binary — only the executable is replaced, so it has to live in a writable folder.
  • Flatpak — the bundle's launcher runs a writable copy from ~/.local/share/EloraNotes, so the update replaces that binary and restarts like the portable build; the sandbox stays as installed.

Settings → Updates shows the version you are running and has the same check on demand, so an update never has to wait for the next launch. The collaboration server is not updated by the app: download the new server build and restart its service as described in Server upkeep.

29 Run from source

You need a Rust toolchain. On Linux, NixOS and macOS the repository includes a launcher that sets up the environment:

./run.sh

Otherwise build and run with Cargo:

cargo run --release

The collaboration server builds on its own, without the GUI libraries a headless machine would not have:

cargo build --release --no-default-features --bin elora-server
ELORA_SERVER_DIR=~/.config/elora-server ./target/release/elora-server init
./target/release/elora-server run

Notes and settings are found in Documents/EloraNotes unless you point the app elsewhere with --dir or ELORA_NOTES_DIR.

For development, cargo test runs the unit and integration suites, and cargo clippy --all-targets -- -D warnings with cargo fmt --check is what CI enforces. The app and server share the protocol in src/net.rs; a client and server built from different protocol versions refuse each other rather than guessing.

30 FAQ

Can I sync notes with Dropbox, OneDrive or Syncthing?

You can put the notes folder inside a synced folder and let the file sync service copy it. That is file sync, not live collaboration: if two machines edit the same note at the same time, the service will produce a conflicted copy and EloraNotes has no way to merge it. Use the shared library when two people need the same note at the same time; use folder sync for one person moving between machines, and let it settle before editing elsewhere.

Can I have more than one vault?

Not inside the window. The app opens one notes folder at a time; relaunch with --dir or ELORA_NOTES_DIR for another. The shared library is separate from the local vault, so a connected server effectively gives you a second set of notes in the same window.

Is there encryption or a password on my local notes?

No. Local notes are plain Markdown; use full-disk encryption (FileVault, BitLocker, LUKS) if the disk needs protecting. The shared library is encrypted in transit with TLS, but the server stores notes in the clear so it can serve them.

Does it need an account or the internet?

No account, and no internet for local notes. The app reaches the network only for the update check, pictures written with http(s) links, and a shared library you configured.

Is there a mobile app?

No. EloraNotes is a desktop app for Linux, macOS and Windows.

Why does the file name not change when I rename a note?

The file name is an ID fixed when the note is created; the title lives in title:. Keeping the file name stable means pictures, backups and the server's copy never have to chase a moving path. Rename the file by hand if you prefer — the app will read its title from the frontmatter and keep working.

Where is a deleted note?

In the notes folder with trashed: true, listed under Trash. Nothing is deleted from disk until you choose Delete Forever.

What happens if I edit a note in another editor?

Do it while EloraNotes is closed. The app writes the open note on every keystroke, so an external edit made while the note is open will be overwritten. On the server, a note's body is re-read when it is next opened, so editing server files between sessions is fine.

How do I reset the look?

Reset all settings to defaults at the bottom of Settings restores theme, colours, sizes, card style and sort. Notes are untouched. For a complete reset, close the app and delete .elora-settings.json from the notes folder — you will lose the server profile and identifier with it, so copy the identifier first if you rely on it.

I lost my identifier. What now?

Notes restricted to the key made from it cannot be opened by a new identifier. Ask the server operator to release your name, then clear the identifier from .elora-settings.json (or delete the file) so the next launch makes a fresh one, and have the note's owner add your new identity. If you still have the old computer's settings file, its identifier value is the secret — copy it before resetting anything.

Can I run more than one shared library?

The app remembers one server profile at a time. Disconnect, change the address, port and password, and connect to another; the notes of the first library stay on its server and disappear from this window while you are on the second.

How do I back everything up?

Copy the notes folder. That includes the settings file, every note and attachments/. If you run a server, copy its data folder as well: the notes, config.json, the certificate and people.json are all in it. Restoring is copying the folders back.
